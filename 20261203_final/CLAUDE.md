## 2. 工作方式

1. **先读后做**：开始一个阶段前，先读语义模型、本文件、`ROADMAP.md`、`DECISIONS.md`、`DEVLOG.md`。
2. **任务清单**：所有工作都在 `20261203_final/ROADMAP.md` 里，按里程碑分组，每项任务都有"完成标准"。同时用任务工具跟踪当前会话的进度。
3. **一步一步自己推进**：一次只做一项任务。做完要跑测试、跑基准、在浏览器里看效果，然后提交，在 ROADMAP 里勾掉，再开始下一项。不要每做完一步就停下来问。
4. **提交**：每项任务至少一次提交，信息写清楚做了什么。不要强制推送，不要改写已推送的历史。
5. **决定**：语义模型 §17 里的问题，以及做的过程中遇到的设计选择，先选一个合理的默认值，记到 `DECISIONS.md`（选了什么、为什么、怎么改回来），然后继续做。
6. **只在这几个检查点停下来等我确认**：
   - 任务清单写完之后
   - 美术风格样张（style frame）做完之后
   - 合并 PR、部署 GitHub Pages、删除文件或文件夹之前
   - 任何不可逆、又可能两种都合理的操作之前
7. **日志**：每次会话结束前，在 `DEVLOG.md` 里写几行：做了什么、下一步是什么、有什么问题。这样下次会话能直接接上。

## 3. 代码效率（硬性要求）

- **模拟核心不碰 DOM**（`src/sim/`），能在 Node 里跑，方便测试、基准和 Web Worker 并行评估。
- **用 typed array 存网格**：`Float32Array`、`Uint8Array`、`Int32Array`。不要每个格子一个对象。坐标用 `idx = j * W + i`。
- **几何固定，所以能预计算的都离线算好**：视线表、visibility fingerprint、地形派生量（坡度、开敞度、积雪漂移系数）都由 Node 脚本在构建时生成，存成二进制 `.bin` 加一个小的 JSON 元数据文件。干预方案（路灯、取暖棚）只做局部重算。
- **寻路**：A* 加二叉堆，重规划有频率上限（参考模型 §12）。行走图按 agent 种类分别缓存。
- **评估**：自动模式的 epoch 在 Web Worker 里无头运行，按 CPU 核数并行跑一个 EvaluationSuite 里的多个 round；用公共随机数保证不同方案之间可比。
- **渲染**：树、石头用 `InstancedMesh`，远处用 LOD 或 impostor。雪面用一张高度纹理更新，不要每帧重建几何。三维视图和二维地图共用同一份状态。
- **性能目标**（`npm run bench` 检查，目标是普通笔记本）：
  - 无头跑一个 900 tick 的 round：< 150 ms
  - 一个 24 round 的 EvaluationSuite：< 3 s（并行）
  - 渲染：1080p 稳定 60 fps
  - 首屏加载：< 3 s；烘焙数据 gzip 后 < 15 MB
- **先测量再优化**：先写 `bench/`，优化之前和之后都记下数字。
- 所有可调参数集中在一个 `config.js` 里，跟以前的作业一样。
- 不用构建工具，沿用之前的结构：纯 HTML 加 ES modules；three.js 用 import map 从 jsDelivr 加载；Node 18+ 跑 `node --test`。只有确实需要时才加依赖，加之前先写进 DECISIONS。

## 4. 美术方向：动画风格和写实风格之间的平衡

**写实的部分（来自数据，不能编）**
- 真实的地形起伏、树的位置和高度、路网、水面、Belvedere Castle 的位置
- 积雪深度、能见度、风向、时间都来自 2016 年 1 月那晚的真实观测
- 雾的浓度直接由能见度数据决定

**风格化的部分（让它好看、好读）**
- 形体简化：树做成几种程式化的轮廓，靠尺寸和颜色变化做出差异，不追求照片级的模型
- 有限的色板：夜晚的冷蓝和灰紫做底，路灯、手电筒、取暖棚用暖橙色做对比。暖光等于安全，这条视觉规则要贯穿整个游戏
- 柔和的渐变着色或轻度卡通着色，加一层柔和的描边或边缘光，保证剪影在雪夜里也清楚
- 雪的质感偏手绘：飘雪、地面上的脚印、被风吹出的雪堆
- 怪物要原创、风格化：由根须构成，有发光的眼睛，延续 Frostroot 前几周的设定
- 界面尽量做成游戏世界里的一部分，比如手电光圈、呼吸白雾表示体温，不要满屏都是面板

**流程**
- 先做一张风格样张：一个固定机位的 Ramble 场景，有雪、路灯、两个幸存者和怪物，再附 3 到 5 个参考方向的文字描述。我确认之后再全面铺开
- 所有美术资源都要原创或使用可以商用的授权，不要临摹或复用现有游戏、电影的角色和素材
- 浅色和深色界面都要能读；手机宽度下界面不能坏
